# Noesis 的 docmd 迁移设计

## 目标

将公开笔记站点从 Quartz 完整迁移至 docmd，同时保留现有 Markdown 内容、Obsidian 同步流程、GitHub Pages 部署和自定义域名 `notes.cavill.site`。

## 范围

- 以 `content/` 作为 docmd 源目录，并输出到 `site/`。
- 使用 docmd 默认主题、自动导航、搜索、SEO、站点地图和 AI 上下文；不复制 Quartz 的图谱、反向链接、标签页、阅读模式或自定义组件。
- 安装并启用官方数学插件，以渲染现有的 `$` 与 `$$` LaTeX 公式。
- 将现有目录页及同步脚本生成的 Obsidian `[[双链]]` 替换为相对 Markdown 链接。
- 将 GitHub Pages 工作流改为构建并发布 `site/`。
- 移除 Quartz 运行时代码、配置、插件、构建脚本和生成的 `public/` 产物。

## 不保留的功能

不启用 docmd 的 Git 插件。因此页面不显示贡献者、提交记录或最后更新时间；Quartz 以前显示的贡献者也不会出现在新站点中。

完成站点迁移并验证后，以当前工作树创建一个仅由仓库所有者署名的根提交，强制替换远端 `main`。这会移除 GitHub 上旧的提交历史和其贡献者统计；已知没有 PR，因此不需要保留旧提交链接。

不加入额外主题、分析、AI 聊天、PWA、评论或自定义转换器。默认功能已覆盖公开知识库所需的阅读、检索和发布能力。

## 实施结构

- 新增 `docmd.config.json`，仅配置标题、规范 URL、源目录、输出目录和数学插件。
- 更新 `package.json` 为 docmd 的开发、构建和链接校验命令；保留 `sync:obsidian` 及其 Node 测试。
- 更新 `.gitignore`，忽略 `site/`；更新 Pages 工作流以执行 `npm ci`、docmd 构建并上传 `site/`。
- 同步脚本继续筛选公开笔记、生成目录索引和清理陈旧内容，但目录索引生成标准 Markdown 链接。

## 验证

- 运行同步脚本测试，确认内容同步行为未回归。
- 运行 docmd 生产构建和内部链接校验。
- 检查首页、普通笔记、包含公式的笔记和目录页链接。
- 检查生成页面不包含贡献者、Git 元数据或 Quartz 标识。
